# FaceUnlock

맥북 화면이 잠겼을 때 카메라로 얼굴을 알아보고 자동으로 잠금을 푸는 메뉴바 앱입니다.

Xcode 없이 Command Line Tools만으로 빌드됩니다.

---

## ⚠️ 먼저 읽어주세요

이 앱은 **Apple의 Face ID가 아닙니다.** 이름이 비슷할 뿐 보안 수준은 전혀 다릅니다.
켜기 전에 아래 네 가지를 이해하고 받아들일 수 있는지 판단해 주세요.

### 1. 2D 웹캠이라 스푸핑에 취약합니다

내장 카메라는 깊이를 재지 못합니다. Apple의 Face ID는 3만 개의 적외선 점을 쏘아
얼굴의 3D 형상을 읽지만, 이 앱은 평면 이미지 한 장만 봅니다.

눈 깜빡임 확인(liveness)이 들어 있어 **인쇄된 사진으로는 열리지 않습니다.**
하지만 **당신이 눈을 깜빡이는 영상을 휴대폰으로 재생하면 뚫립니다.** 이건 이 앱의
설계 한계이고, 고칠 계획이 없습니다. 깊이 센서나 적외선 카메라가 있어야 하는 영역입니다.

### 2. 로그인 비밀번호를 기기에 보관합니다

macOS에는 서드파티 앱이 화면 잠금을 직접 해제하는 공개 API가 없습니다. 그래서 이 앱은
저장해 둔 비밀번호를 잠금 화면에 **대신 타이핑**합니다. 즉 비밀번호를 복호화 가능한
형태로 갖고 있어야 합니다.

할 수 있는 보호는 다 했습니다:

- 대칭키를 **Secure Enclave** 안에서만 유도합니다 (P-256 자기 ECDH → AES-GCM)
- Keychain에는 암호문만 들어갑니다. 키체인을 통째로 덤프해도 복호화할 수 없습니다
- 다른 Mac으로 옮기면 열리지 않습니다 (`ThisDeviceOnly`)
- 평문은 `String`이 아니라 `[UInt16]`로만 다루고, 사용 직후 0으로 덮습니다

그래도 **이 Mac을 물리적으로 손에 넣고 로그인까지 한 공격자에게는 방어가 되지 않습니다.**
잠금 화면에서 써야 하므로 생체·암호 확인을 걸 수 없기 때문입니다.

### 3. FileVault 부팅 화면에는 적용되지 않습니다

전원을 켜고 처음 뜨는 FileVault 화면은 macOS가 아직 뜨기 전이라 앱이 돌 수 없습니다.
**로그인 후 화면 잠금**에서만 동작합니다.

### 4. 기본값은 꺼짐입니다

설치해도 아무 일도 일어나지 않습니다. 설정에서 직접 켜야 합니다.

> 이 소프트웨어는 **아무런 보증 없이** 제공됩니다. 사용에 따른 모든 위험은 사용자가
> 부담합니다. 자세한 내용은 [LICENSE](LICENSE)를 참고하세요.

## 요구 사항

- macOS 14 이상, Apple Silicon
- Xcode Command Line Tools (`xcode-select --install`)
- 모델 변환용 Python 3.11 또는 3.12 (`brew install python@3.11`)
  — coremltools가 3.13+ 를 아직 지원하지 않습니다

## 설치

### 소스에서 빌드 (권장)

직접 빌드하면 격리(quarantine) 속성이 붙지 않고, 코드서명이 안정적이라
업데이트할 때 권한과 Keychain 항목이 유지됩니다.

```bash
git clone https://github.com/<your-account>/FaceUnlock.git
cd FaceUnlock
make model      # ArcFace 모델 내려받기 + CoreML 변환 (최초 1회, 수백 MB)
make install    # /Applications 에 설치
```

### 배포된 DMG 사용

Apple Developer Program($99/년)에 가입하지 않아 **공증(notarization)이 없습니다.**
다운로드하면 "손상되었기 때문에 열 수 없습니다"라는 경고가 뜹니다. 파일이 손상된 게
아니라 공증이 없어서 나오는 메시지입니다.

```bash
xattr -dr com.apple.quarantine /Applications/FaceUnlock.app
```

또는 시스템 설정 → 개인정보 보호 및 보안 → 아래로 스크롤 → **확인 없이 열기**.

> 모르는 개발자의 서명 없는 앱에 이런 조치를 취하는 건 일반적으로 위험한 일입니다.
> 신뢰할 수 없다면 소스에서 직접 빌드하세요. 그게 이 저장소를 공개하는 이유입니다.

## 설정

1. 메뉴바의 얼굴 아이콘 → **설정…**
2. **카메라** 권한 허용 — 얼굴 인식용
3. **손쉬운 사용** 권한 허용 — 잠금 화면에 비밀번호를 입력하는 데 필요합니다
4. **얼굴 등록…** — 9가지 자세를 안내에 따라 촬영합니다
5. **로그인 비밀번호** 입력 — 저장 전에 실제 비밀번호가 맞는지 확인합니다
6. **얼굴로 잠금 해제** 켜기

`Ctrl`+`Cmd`+`Q`로 잠근 뒤 카메라를 보면 몇 초 안에 열립니다.

### 조정할 수 있는 값

| 항목 | 기본값 | 설명 |
|---|---|---|
| 인식 엄격도 | 0.48 | 높일수록 타인이 열 확률은 줄지만 본인도 자주 실패합니다 |
| 눈 깜빡임 확인 | 켜짐 | 끄면 **인쇄된 사진으로도 열립니다.** 켜두세요 |
| 인식 제한 시간 | 20초 | 지나면 포기하고 비밀번호 입력으로 넘어갑니다 |

## 동작 방식

```
화면 잠김 (com.apple.screenIsLocked)
  → 카메라 시작 (잠긴 동안에만 — 표시등이 계속 켜져 있지 않도록)
  → Vision 얼굴 검출 + 5점 랜드마크
  → 품질 게이트 (크기·가장자리·선명도)
  → 유사변환으로 112×112 정렬 + 노출 정규화 + CLAHE
  → ArcFace CoreML → 512차원 임베딩
  → 등록 얼굴과 코사인 유사도, 연속 3프레임 일치 요구
  → 눈 깜빡임 챌린지 → 깜빡임 직후 신원 재확인
  → 잠금 상태 재확인 → 비밀번호 주입 → Return
```

### 왜 연속 3프레임인가

한 프레임의 우연한 일치로 열리면 안 되기 때문입니다. 얼굴이 시야에서 사라지면
카운트를 0으로 되돌립니다 — 인식된 뒤 다른 사람으로 바꿔치는 걸 막습니다.

### 왜 깜빡임 후에 다시 확인하는가

눈을 감고 있는 동안 얼굴이 바뀔 수 있습니다. 깜빡임이 감지되면 임베딩을 한 번 더
확인하고, 일치하지 않으면 처음부터 다시 시작합니다.

### 가장 중요한 안전장치

주입 **직전에** 잠금 상태를 다시 확인합니다. 이미 풀린 화면에 주입하면 비밀번호가
눈앞에 그대로 타이핑되고, 열려 있던 문서나 터미널에 들어갑니다. 상태를 확인할 수
없으면 "잠기지 않음"으로 간주하고 주입하지 않습니다 — 실패하는 쪽이 안전합니다.

## 모델에 대하여

얼굴 임베딩은 **InsightFace의 ArcFace (`buffalo_l` / `w600k_r50`)** 를 씁니다.

이 가중치는 **비상업 연구용 라이선스**라 이 저장소와 배포물에 포함하지 않습니다.
`make model`이 [InsightFace 공식 릴리스](https://github.com/deepinsight/insightface/releases/tag/v0.7)에서
직접 내려받아 CoreML로 변환합니다. 상업적 용도로 쓰려면 라이선스를 직접 확인하세요.

변환 스크립트는 PyTorch 출력과 CoreML 출력의 코사인 유사도가 0.999 이상일 때만
통과시킵니다. 여기서 어긋나면 인식이 통째로 무의미해집니다.

## 개발

```bash
make debug        # 빌드 + ad-hoc 서명
make run          # 빌드 후 실행
make log          # 로그 스트림 (비밀번호·임베딩은 절대 찍지 않습니다)
make aligntest && ./build/aligntest --selftest    # 안전 가드·정렬 기하·상하 방향 검증
make xcheck       # Swift 전처리 ↔ 원본 ONNX 교차 검증
./build/aligntest a.jpg b.jpg                      # 두 사진의 유사도 비교
make release      # 최적화 빌드
make clean
```

`--selftest`는 사진 없이 돌아갑니다. CoreImage(좌하단 원점)와 비트맵(좌상단 원점)
사이에서 상하가 한 번 뒤집히면 임베딩이 조용히 망가지는데 에러가 나지 않아서,
이걸 자동으로 잡아내려고 만들었습니다.

### 검증 항목

빌드가 통과한다고 동작이 맞는 건 아니라서, 조용히 틀릴 수 있는 곳마다 검사를 걸어두었습니다.

| 검사 | 무엇이 틀리면 잡히나 | 실행 |
|------|---------------------|------|
| 잠금 가드 | `screenIsLockedNow()` 가 풀린 화면을 잠김으로 보고 → **비밀번호가 눈앞에 타이핑됨** | `--selftest` |
| 유사변환 잔차 | 5점 정렬 수식 오류 | `--selftest` |
| 렌더 상하 방향 | CoreImage(좌하단 원점) ↔ 비트맵(좌상단 원점) 뒤집힘 | `--selftest` |
| 전처리 교차 검증 | RGB/BGR 뒤바뀜, NCHW/NHWC 착각, 정규화 상수 오류 | `make xcheck` |
| 모델 변환 게이트 | 레이어 누락·transpose 실수(FP32 ≥ 0.9999), 양자화 손실(FP16 ≥ 0.995) | `make model` |

가운데 셋은 **에러를 내지 않고 조용히 틀리는** 종류입니다. CoreML 은 채널 순서를 바꿔 넣어도
군말 없이 512차원 벡터를 돌려주고, 증상은 "얼굴은 잡히는데 절대 일치하지 않는다"로만 나타납니다.

현재 측정값 — 전처리 교차 검증 `cos = 0.9987` (편차 2.92°), 모델 변환 FP32 `cos = 1.000000`,
FP16 `cos = 0.9976` (3.95°). 판정 임계 0.48 은 각도로 약 61° 이므로 이 정도 편차는 무시할 수준입니다.

## 알려진 문제

- **ad-hoc 서명이라 빌드마다 서명 정체성이 바뀔 수 있습니다.** 새 버전을 덮어쓰면
  손쉬운 사용 권한을 다시 허용하고 비밀번호를 다시 등록해야 할 수 있습니다.
  앱이 Keychain을 읽지 못하면 설정 화면에서 재등록을 안내합니다.
- 외장 웹캠보다 내장 카메라를 우선합니다.
- 아주 어두운 방에서는 인식이 실패합니다. 화면 불빛만으로도 대체로 되지만
  안 되면 비밀번호로 로그인하면 됩니다.
